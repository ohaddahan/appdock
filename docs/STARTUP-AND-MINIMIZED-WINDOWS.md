# Startup rules, clearer tabs, and minimized windows — 2026-09-10

## User controls

- **AppDock → Auto-add at Startup:** check detected apps to remember them. Checked entries stay available in the menu when their apps are not running, so they can be disabled later. Rules persist in the existing workspace JSON as an optional `startup_apps` array, keyed by exact bundle ID. Older version-1 files load with no rules.
- **Startup behavior:** once discovery and workspace geometry are ready, add every eligible window of each checked app, including minimized windows, as the user confirmed. Already-attached windows are skipped individually; absent apps are not launched. Only the first selected window is restored at startup; the remaining windows restore when their tabs are selected. See [the follow-up validation](STARTUP-ALL-WINDOWS.md). Startup rules are separate from old tabs and live AX handles. Release does not cause automatic reattachment during the session. Manual selection, editing, release, pause, quit, or startup-rule changes cancel remaining startup jobs.
- **Tabs:** stronger outlined backgrounds, a brighter active fill/border/underline, and a shared tab surface behind the close button. Existing confirmed-selection and disconnected-action distinctions remain. [Native design fixture](review-evidence/startup-tabs-minimized/design.png) was rendered and inspected; its tabs are intentionally disconnected dummy entries.
- **Minimized picker entries:** show a Minimized label. Adding restores the window and rechecks its normal docking capabilities. Release restores its original minimized state.

## Minimized-window reproduction and fix

The unmodified discovery filter returned **zero entries for three minimized native windows**: [failing reproduction](review-evidence/minimized-before/Minimized.log). A read-only probe of those disposable windows found three AXWindows entries, each reporting `AXWindow` / `AXDialog`, `AXMinimized=true`, and `AXMain` not settable: [probe log](review-evidence/minimized-probe/Minimized.log). The old standard-window subrole filter discarded them before eligibility checking, and the old AXMain requirement would also reject them.

Discovery now accepts that transient subrole when the window is minimized, restorable, non-modal, non-fullscreen, and has a valid restoration frame. It does not unminimize windows during a scan. After explicit/manual or configured startup attachment, normal role and capability validation runs before geometry/focus changes. Failed validation rolls back. This uses Apple's explicit minimized-state attribute; [Apple's attribute reference](https://developer.apple.com/documentation/applicationservices/carbon_accessibility/attributes?changes=_4) defines that state independently of main-window status.

The new native `Minimized` fixture discards cached backend handles before rediscovering the already-minimized windows. All three now appear eligible; attaching restores the chosen window, and releasing it restores minimization. This demonstrates the general native filter defect. WhatsApp and Spotify themselves were not attached, minimized, or otherwise changed during validation.
