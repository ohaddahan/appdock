# Architecture

`model.rs` defines desktop coordinates, saved identities, capabilities, and `WindowBackend`. `engine.rs` owns attachment snapshots, selection, interruption handling, rollback, and restoration. `startup.rs` resolves explicit saved app rules once per launch. `persistence.rs` validates versioned workspace JSON and uses an atomic file replacement. `macos.rs` owns retained Accessibility elements. `worker.rs` runs the backend and persistence outside the main thread. `ui.rs` owns AppKit windows, controls, menus, gestures, icons, and shortcut registration on the main thread. `picker.rs` owns the themed inline window-selection view and rows.

AppKit calls that show or hide a window can synchronously reenter its delegate. Picker presentation, attachment, and exit release the UI `RefCell` guard before changing window visibility. The key-window callback sets a separate `Cell` flag and reorders the backdrop below its cached selected-window number without borrowing UI state. The timer consumes the flag and schedules raising.

## Identity and control

Live handles are monotonically assigned IDs backed by retained AX elements. Discovery matches elements using CF equality within a process, never a title. Startup clears all previous-session tabs before constructing the worker or discovering windows. Apps are attached manually unless the user has enabled an explicit startup rule for their bundle ID. Confirmed closed windows remove their saved tab. Polling checks current AXWindows membership once per process, even when an old AX object still returns cached attributes. Failed AXWindows reads retain live handles. A timeout pauses control and retains the restoration snapshot.

The worker polls attached windows for lifecycle and geometry changes. This first backend uses polling rather than AXObserver callbacks; applications vary in notification support. Space changes arrive through `NSWorkspaceActiveSpaceDidChangeNotification`. Each AX request has a one-second timeout. AppKit never waits for AX IPC. Several operations can accumulate latency for an unresponsive application, but the UI remains independent.

The mailbox coalesces pending geometry and app-list updates. Switch generations invalidate queued requests and check again during preparation. The next window is positioned and focused without minimizing the previous window. An already minimized target is restored before selection. Failed preparation rolls back the target and attempts to refocus the previous selection. Release removes the live attachment and saved tab before restoration IPC. Failed window-control operations retain a separate detached recovery snapshot, available through Retry restoration; the observer never moves released windows. A new explicit attachment supersedes a detached recovery for the same window. A failed exit retains only snapshots still requiring restoration. Closing never calls a target application's quit operation.

Geometry uses global desktop points with a top-left origin. Cocoa rectangles convert using the primary screen's height, including negative coordinates on secondary displays. AX returns the actual window frame after resizing so minimum-size constraints do not cause a repeated resize loop. Readback and bounded waits account for asynchronous native minimization animations.

## Boundaries and known limitations

External windows are not embedded or reparented. AppDock uses a non-opaque AppKit controls window and a separate opaque, borderless, normal-level backdrop. Its content view paints the control strip and an 8-point frame around a transparent app area while a window is attached, so bringing AppDock forward cannot obscure the external app during asynchronous focus restoration. The selected external window is ordered above the manager during normal interaction. The backdrop is ordered below both windows and above inactive tabs using public `NSWindow::orderWindow:relativeTo:`. It covers the union of docked frames, including app-enforced minimum sizes. Empty workspaces keep the full controls-window background. The backdrop is hidden when docking is paused, the manager is hidden/minimized, selection is absent, or the workspace is closing. Native title bars, Dock entries, Spaces behavior, and application-specific window policies remain macOS-owned. All previously selected windows follow manager geometry so inactive windows stay behind the cover. The drag sampler moves the backdrop too. After manager movement settles, the worker raises the selected window again. Manual target movement retains ownership; the observer waits for mouse release and restores the docking frame. Fullscreen, dialogs, minimization and desktop changes still pause control.

There is one workspace per data directory, guarded by an advisory file lock. Different data directories can still attach the same external window: use only one manager for a given window. AppDock does not implement cross-process window ownership or crash recovery. Avoid Force Quit if you want automatic restoration.

Dialogs are detected through AXModal/AXSheets, and fullscreen through AXFullScreen when supported. Apps that omit those attributes may require manual pausing/releasing. Window identity from AXIdentifier is supplied by the app; absent and ambiguous identifiers are deliberately not guessed. Foreground hotkey registration is polled and has a small transition window.

All unsafe code is at Objective-C/CF boundaries: retained Core Foundation ownership, type-checked AX values, typed geometry encoding, native delegate/target methods, and native initialization. No private window-server APIs are used.

API references: [AppKit bindings](https://docs.rs/objc2-app-kit/0.3.2/objc2_app_kit/), [Accessibility bindings](https://docs.rs/objc2-application-services/0.3.2/objc2_application_services/), [global-hotkey](https://docs.rs/global-hotkey/0.7.0/global_hotkey/).

Discovery checks canonical AX equality for ownership, including aliases with different local IDs. An invalid AX read is confirmed against the application’s current window list before declaring closure. Unique AX identifiers can rebind replaced AX objects while retaining the original restoration snapshot. If a tab is disconnected and identity cannot be recovered, Add is blocked for that app until the tab is replaced or released; this avoids guessing from a title or creating duplicate saved tabs.

The worker mailbox uses a condition variable, so commands wake it immediately instead of waiting for a 100 ms sleep. Latest geometry takes priority over background commands. Position-only manager movement writes AXPosition without AXSize, settling sleeps, or full-state readback. Size changes still use checked geometry operations. Geometry persistence waits for 250 ms of inactivity; lifecycle observation stays out of continuous movement and resumes afterward. The native APIs and compositor remain asynchronous, so this is not a guarantee of frame-perfect synchronization between independent app windows.

Live native title-bar dragging switches the main run loop into `NSEventTrackingRunLoopMode`. A separate nominal 120 Hz timer is explicitly registered in tracking and default modes and sleeps outside dragging. It queries `CGWindowListCopyWindowInfo` for AppDock's own exact window number, uses WindowServer bounds to compute the target area, and publishes only changed frames to the coalescing worker. It does not depend solely on deferred move notifications or sample external windows for identity. The regular 150 ms UI refresh does not run in the tracking loop. See [Apple's run-loop mode documentation](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Multithreading/RunLoopManagement/RunLoopManagement.html).

UI action selection is separate from the backend's live-window selection. A disconnected saved tab is still selectable and removable: action targeting falls back to an existing saved tab when no live window is selected. Every tab also has an explicit × control carrying its own tab ID.

The compact native interface mirrors Terminator's current default palette (`terminator/crates/core/src/appearance.rs`) and 13-point Inter styling (`terminator/crates/app/src/appearance.rs`). The Inter font is embedded with its license and registered process-locally through Core Text. Controls remain AppKit, and their app area remains transparent above the separate opaque backdrop while attached. Double-clicking the native tab button starts an inline NSTextField; Enter/blur commits and Escape cancels. Rename state is separate from live-window selection, and the target is not raised while the inline editor has focus. Only + and per-tab × remain permanent actions. Permission, Resume and replacement controls are conditional; quitting uses the normal window/menu actions.

## Backdrop stacking anchors

Retained AX elements remain the authority for window identity. After AXRaise and exact AXFocusedWindow readback, the backend samples the frontmost normal WindowServer window for that process and checks its AX frame before caching its number for presentation only. It waits for a known number to reach the front and refuses numbers already assigned to a different AX window: AX focus can settle before WindowServer ordering, particularly for same-app tabs with identical geometry. AX-object rebinding clears the cached number. No window titles, screenshots, Screen Recording permission, or private AX-to-window-number API are used.

The UI uses [Apple’s public relative window ordering API](https://developer.apple.com/documentation/appkit/nswindow/order(_:relativeto:)) and [WindowServer metadata](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:)). Window ordering does not make the backdrop key. Its callback-safe ordering handle also keeps it below the selected app when AppDock becomes key for inline rename. External activation and compositor scheduling remain macOS-owned; this is visual occlusion, not embedded or hidden application state.

## Startup cleanup and release geometry

`persistence::load_for_launch` validates the workspace, removes previous-session tabs, and saves the cleared state before constructing the UI/worker. This preserves geometry, shortcuts, and optional `startup_apps` rules while preventing implicit reconnection from old tabs or AX identifiers. `Startup` resolves those explicit rules once, after completed discovery and current geometry are available. It schedules one eligible window per matching bundle; multiple windows require manual selection. The worker handles startup attachments between normal commands, and manual input cancels remaining jobs. Periodic discovery refreshes the picker without reattaching released windows. The old automatic-reconnection and conditional-pruning paths were removed. Lifecycle polling still removes confirmed closed windows and persists changes. Presentation fixtures add dummy tabs after fresh-session loading.

Release and exit use a separate restoration outcome: exact geometry or adjusted geometry. Explicit release requests the original frame and minimized state. Close defaults to preserving current visibility for successfully docked windows while restoring original geometry; users can disable Keep Apps Open on Close to restore original minimization too. Startup windows never selected are unregistered without writes. Incomplete preparation/rollback snapshots retain full restoration requirements. A size/position difference is logged as an adjustment and cannot trap the user in Retry close; actual AX failures, fullscreen/dialog interruptions and minimized-state failures retain retry snapshots. Already-restored windows require no writes. Switch rollback continues to require exact geometry. The worker no longer suggests granting permission for every kind of restoration error.

The bordered + Add App control shares a left-aligned `NSTitlebarAccessoryViewController` with the visible AppDock title, keeping it immediately beside the title. The window retains its native title for Accessibility while its default visual title is hidden. The control uses the same `addWindow:` action. The tab scroll view uses the full content width. The accessory remains in AppKit’s native title bar and does not change the docking-area calculation.

## Compact tabs, framed app area and rename focus

New tab labels are the application name only. Tabs occupy 160 points and use a single-line, truncating cell. Outlined rounded backgrounds include the close-button area; confirmed active tabs use a brighter fill, border, and underline. A disconnected action target retains its distinct left marker. The idle rename/reorder status text is removed. The header uses 36 points normally and 64 only while status text or recovery/permission actions require a row.

Both native drag sampling and normal layout inset the target frame by 8 points on every side. The surface paints these margins, leaving the exact target area transparent. The manager grows when the selected app returns a larger minimum size. Growth waits until the worker acknowledges the current requested area, avoiding resize feedback from stale snapshots. This is a visual AppDock frame; the external window retains its own macOS title bar and window identity.

Renaming sets an atomic focus-suspension flag before cancelling queued switch/raise requests. A worker barrier acknowledges completion of earlier focus IPC. Only then does AppDock activate and present its editable field. The AX backend checks suspension between focus operations; later Raise requests cannot take the keyboard during editing. Finishing or cancelling releases the suspension. The dedicated rename NSTextView handles Ctrl+A and Cmd+A in both key-down and key-equivalent paths; other controls use the default field editor. Routing state is stored outside the UI RefCell because AppKit can synchronously request a field editor during UI updates. See [Apple’s field-editor guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/TextEditing/Tasks/FieldEditor.html).

## Inline picker and direct app activation

The picker is an opaque NSView within AppDock’s content area. It replaces the NSPanel and NSPopUpButton with themed search, scrollable ChoiceRow buttons, a result count, empty feedback and Refresh/Cancel/Attach actions. It preserves selection by exact WindowId, disables attachment when the selection disappears, and puts process/window metadata in tooltips. It lays out with the manager’s content area. Picker search uses the same scoped field editor and worker focus barrier as rename. The manager paints its full surface while the picker is visible, covering the selected external window without minimizing it. Closing the picker restores the transparent app area and releases focus suspension. Tab clicks dismiss the picker; search supports arrows, Enter and Escape.

Worker snapshots publish cached WindowServer numbers and owner PIDs for live attachments. When a managed app is foreground, the UI checks its frontmost normal window against those exact cached numbers. An unrelated window from the same app does not qualify. The UI reveals AppDock by ordering the manager immediately below the matched app, without making it key, and changes selection when another docked window was activated directly. Pending tab-switch requests are tracked so observing an in-progress activation does not cancel/requeue that same switch. Picker/rename focus ownership, pause state and explicit manager minimization suppress this automatic reveal.

## Pointer routing

A transparent full-size AppDock window above an external app is not treated as a click-through guarantee. Normal stacking is selected app, manager frame, opaque backdrop, then inactive apps. This keeps the manager visible around the app while the app itself receives mouse input. The backdrop chooses the lower of manager/app as its stacking anchor, avoiding repeated conflicting reorder operations.

The rename field can remain key while the manager is ordered below the app. Clicking away commits rename after the manager resigns key; that callback uses a Cell flag to avoid reentrant UI borrowing. The inline picker still deliberately comes above the app and paints an opaque surface while it is open.

Native regression checks call [windowNumber(at:belowWindowWithWindowNumber:)](https://developer.apple.com/documentation/appkit/nswindow/windownumber(at:belowwindowwithwindownumber:)) at several app-body points and at the tab strip. These validate WindowServer mouse routing rather than relying on bitmap transparency or keyboard-focus checks alone.

## App notification badges

The main thread supplies the Dock PID and exact application bundle/executable paths for current live attachments. Coalesced ReadBadges commands run on the worker, use public Accessibility reads of Dock AXURL/AXStatusLabel metadata and match file paths rather than display names. Requests are nominally every 2.1 seconds, skipped while the pointer is down or AppDock owns text input. Scans cap traversal at 128 nodes with a 250 ms between-node budget and 200 ms per-request timeout. Dock reads are optional: errors do not pause docking or change focus. No messages or Notification Center databases are read, and badge values are never persisted.

Snapshots contain current nonempty labels keyed by TabId. Release/closure removes stale badges, and requests validate the live WindowId before applying results. Exact numeric labels become counts up to 99+; nonnumeric labels become a dot. Empty/zero labels clear. Tab drawing reserves room for the badge and title truncation, and badge-triggered tab reconstruction waits until mouse gestures and renaming finish. Tooltip text identifies the source as an app-wide Dock badge. This cannot establish a general per-window pending-action state; missing badges also include unsupported/unavailable sources.

References: [Apple’s Dock badge label property](https://developer.apple.com/documentation/appkit/nsdocktile/badgelabel), [Doll’s Accessibility-based badge monitoring](https://github.com/xiaogdgenuine/Doll).

## Minimized-window discovery

The native reproduction showed normal minimized NSWindows reporting `AXWindow` / `AXDialog` with read-only `AXMain`. Discovery accepts this subrole only when `AXMinimized` is true, geometry is valid, no fullscreen/modal state is active, and restoring is supported. Movement/focus capabilities may be temporarily unavailable while minimized. Picker rows label this state.

`Engine::switch_current` preserves the original minimized snapshot, restores the target, and calls `validate_restored_window` before moving or focusing it. That validation requires the normal standard-window role and full docking capabilities. It allows a cancellable 900 ms readiness budget with 30 ms polling intervals for controls that lag the unminimized flag; an in-flight AX request can outlast that budget. Permission/communication errors propagate with their AX codes. Resume uses the same readiness check. A failed validation rolls back and retains the restoration snapshot. Non-minimized dialogs remain excluded. No discovery scan restores windows merely to inspect them.

## Visible app settings

A title-bar Settings button and AppDock's Settings menu item (Command-comma) open the existing startup menu after the editing/focus barrier acknowledges outstanding native focus work. The menu tracks opening/closing independently of the UI RefCell; its contents are not rebuilt while tracking. New picker, rename, and quit intents cancel a pending Settings popup. Native fixture stages exercise the actual button and popup with a bounded tracking-mode close timer.

`SaveStartupApps` derives a distinct list of live app bundles in tab order, and `ResetStartupApps` clears only that list. Both run and persist on the worker and cancel pending startup jobs. Neither alters attachments, restoration snapshots, geometry, or shortcuts. Successful changes leave the normal status row collapsed, avoiding a geometry change caused by a confirmation message.

The controls window disables its shadow while attached, avoiding an additional shadow along the rectangular transparent cutout. The opaque backdrop uses the same WINDOW palette color as the surrounding frame, so exposed native rounded corners do not reveal a differently colored backing rectangle. The external window's own appearance is unchanged.

Startup registration now selects/restores only the first successful tab. Later startup attachments are marked `deferred_startup` and stay untouched until selection. The flag is cleared before any preparation mutation so a failed rollback cannot be mistaken for an untouched window. Close and Release do not undo external changes to a still-deferred window. `keep_apps_open_on_close` defaults to true for fresh/legacy files, while an explicit false value persists. Resetting startup app choices does not reset this preference.
